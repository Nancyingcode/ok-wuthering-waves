# 长离 / 今汐 / 维里奈导入队伍

此目录保存手动测试的 `1.0.4-candidate` 源码。原始队伍作者为楽山；候选修订保留在导入代码中，通过队伍代码界面导入后生效。

三个角色文件和 `team.json` 与已交付的 1.0.4 导入包内容逐字节一致。仓库的内置角色实现不受此目录影响。

## 构建和导入

在仓库根目录使用项目 Python 环境运行：

```powershell
.\.venv\Scripts\python.exe custom_teams/Changli_Jinhsi_Verina/build.py
```

没有 `.venv` 时可使用 `python`。构建只依赖标准库，输出 `dist/Changli_Jinhsi_Verina_1.0.4-candidate.zip`，也可用 `--output <路径.zip>` 指定位置。

暂停自动战斗，在队伍代码界面导入 ZIP，确认版本为 `1.0.4-candidate` 并使用导入代码后开始新的一场。无需解压。ZIP 根目录仅有 `team.json` 和三个角色文件；文档、构建脚本和测试不进入导入包。

## 已保留的行为

- 今汐要求新的变奏入场凭据；不能用未满协奏、旧缓存或单帧闪满绕过。
- 维里奈交接时补协奏并复查技能、回路；连续两帧确认满协奏后，从原交接位置继续宏。
- 补资源预算为 4 秒，已确认的本次 R 演出最多另留 3.5 秒；技能重发和宏恢复均有上限。
- 确认结算文字后按正常结束处理；没有结算证据时继续保留异常信息。

## 测试与实战证据

离线测试使用模拟时间、读数和输入，只验证控制流程。按仓库现有测试入口运行：

```powershell
.\.venv\Scripts\python.exe -u run_test.py tests/TestLongfengweiImport.py
```

包含迁移的 101 项决策回归，以及导入包内容、可重复构建和真实导入检查器验证。测试只读取本目录源码，不依赖个人安装路径、`logs/`、`configs/` 或历史候选包。

2026-10-31 用户以“通用强化”手动测试三轮，分数为 **5888 / 4692 / 5597**；此前 1.0.3 同 BUFF 两轮为 **4806 / 5051**。1.0.4 有一次“补 A ×1 → 满协奏确认 → 原位续宏 → 后续宏完成”的日志链；新增 E/R/回路补满分支仍无成功实战样本。

已知限制：三轮末尾均未命中结算识别，仍有 HUD/角色确认错误；低协奏仍可能补 A 超时；长离再次出现两次 8 秒攒离火超时。分数波动较大，不能据此认定稳定提升。这次纳入版本管理没有继续修改轮转行为，也没有将候选版本标为已解决上述问题。
