# 椿 / 散华 / 守岸人导入队伍

当前源码为 `1.1.9` 回切倒计时保护候选，基于 `1.1.7` 功能版本，保留 `1.1.6` 六秒回切恢复。`1.1.8` 连续采样及包装已从生产实现撤下，诊断源码和原包备份在 `downloads/chunsanshou-1.1.9/`；历史采样测试归档到 `downloads/chunsanshou-1.1.8/diagnostic-tests/`。

## 依据与范围

1.1.8 单场用户得分 4547，4R、3 次新开花、3 次收尾，没有输出超时或重击补按。本场中途回切前原图尚余 53 秒，原生锁敌约三秒返回失败，随后脱战并在约 0.068 秒后重入同一挑战。实际失败瞬间没有完整图，HUD 是否被变奏遮挡尚不确定。

1.1.9 只在椿回守岸人的临时 `in_combat` 判断中，使用已有 `get_abyss_remaining_time()`：

- 队伍 HUD 可读、没有显式结束条件，且读取到正倒计时，才以挑战仍在继续处理瞬时丢锁。
- 复用现有约 0.4 秒缓存；读取前后及后续输入仍受原回切预算检查约束。
- 倒计时为零/不可读、HUD 不可读、接口不可用或有显式结束条件时，沿用原生检测。
- 如果原生回切检查仍返回 False，单独保存 `combat_check_failed` 故障图与本次尝试耗时；它不等于局部超时。

原六秒总回切预算、首次 4.5 秒与最多一次剩余预算重试，以及输出上限、尾段判据、回路识别、准备补 R 和重击恢复均保持原样。散华和守岸人只更新同包身份。没有把 F 提示当作打断依据：诊断场第三花的全部 14 个样本都有 F 提示，回路仍正常耗尽。

1.1.8 连续采样三段占用执行线程约 2.873 秒，约为输出墙钟的 12.2%，另有后台 PNG 开销。功能候选已移除这部分负载。如果失败时 HUD/倒计时不可读，正计时保护可能不触发。

## 实测状态与已知缺陷

1.1.9 已完成两场手测，分数为 3140、4580，另有一场由用户主动取消；没有完成独立确认，整体稳定性筛选未通过。本次入库保存候选源码、构建器和回归测试，不代表已确认性能提升或解决 80% 回路停滞。

- 正倒计时保护共触发三次，三次交接均有确认。
- 输出段锁敌曾空等约 11.7 秒，随后阶段超时被全局战斗检测吞成脱战；该路径不在当前回切保护范围内。
- 一次回切等待结束时守岸人已在场、倒计时仍有 8.36 秒，但没有重新对账，仍误判脱战。
- 尾段仍有识别断档及最新消耗帧与软超时判定顺序待复核；输出与收尾规则未因此放宽。

## 构建与导入

```powershell
.\.venv\Scripts\python.exe custom_teams/ChunSanShou_Video/build.py
```

没有本地 `.venv` 时可用 `python`；构建只依赖标准库，默认输出 `dist/ChunSanShou_Video_Codex_1.1.9.zip`。

导入时暂停自动战斗，确认版本 `1.1.9`、三个角色均使用“导入代码”。该导入队伍需要显式导入启用。

本轮四次尝试预算已用满：一场诊断、两场候选完成场和一场主动取消，不再补跑确认场。取消场不记零分或算法失败，但保留在尝试记录中。
